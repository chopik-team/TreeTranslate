# TreeTranslate AW 0.7 — Translation Memory Engine

Дата: 23.09.2026. База: AW0.6.2, ветка `codex/next-cycle`.

## Результат

Создан локальный движок памяти переводов перед существующим TranslationRouter. Текст, DOCX, native PDF и распознанный PDF используют один экземпляр памяти в приложении. Подтверждённое безопасное совпадение возвращается без вызова маршрутизатора моделей. При отсутствии подходящего перевода работает прежний Argos/M2M100 pipeline.

Память изначально пуста. Результаты моделей не записываются автоматически. Полного редактора памяти, наполнения, глоссария, дообучения, новых моделей и установщика в этом этапе нет.

## 1. Аудит и архитектура

Проверены `TranslationService`, `HybridTranslationService`, `TranslationRouter`, `TextTranslationEngine`, фабрика движка, `DocumentTranslationService`, `DocumentJob`, сегменты DOCX/PDF/OCR, `LanguageResolver`, PDF fidelity guards, настройки и `RuntimeManager`. Все документы уже передавали перевод общему callback. Поэтому новый переводчик документов не создавался.

Схема вызова:

```text
Text / DOCX / PDF / OCR
  → TranslationKnowledgeEngine
  → LanguageResolver
  → TranslationMemoryEngine
      exact → normalized → explicit numeric template → fuzzy candidate
  → безопасный TM hit: результат + учёт использования
  → miss / unsafe candidate: прежний TranslationRouter → Argos/M2M100
  → прежняя обработка и проверки документа
```

`app/translation_memory` разделён на database, models, repository, normalization, matcher, scoring, engine, knowledge, importer, exporter, maintenance и errors. Qt в пакете не требуется. Обёртка сохраняет доступ к runtime, languages, devices, policy и метрикам Router. `backend_only` намеренно обходит память: замер модели должен действительно вызывать модель.

`TranslationRequest` расширен полями domain/context/document_type с совместимыми значениями по умолчанию. `DocumentConfig` поддерживает domain/context. DOCX пока не передаёт семантический тип каждого абзаца автоматически; контекст можно задать через API. Для PDF остаются существующие защищённые фрагменты, консервативное сохранение и проверки чисел. Защищённый PDF-фрагмент может разбиваться до обращения к TM: запомненная целая фраза не обязана совпасть с частями такого сегмента.

## 2. SQLite, расположение и схема

Пользовательская база: `%LOCALAPPDATA%\CHOPIK Team\TreeTranslate\translation_memory.db`. Переопределение: `TREETRANSLATE_TM_PATH` или аргумент `path`/CLI `--db`. Создаётся лениво при первом обращении, вне каталога программы. Обновление приложения не удаляет её.

Schema v1 хранится в `PRAGMA user_version`. Создание v0→v1 выполняется одной транзакцией `BEGIN IMMEDIATE`, с повторным чтением версии после получения блокировки. Неизвестная более новая версия, повреждённая база и конфликт существующей схемы приводят к отказу памяти без удаления данных. Следующая версия должна добавляться отдельной миграцией; миграции в несуществующую v2 не заявляются.

Таблица `units`: id; source_language/target_language; source_text/source_normalized/target_text; source_hash/normalized_hash; domain/context; origin/status/quality; created_at/updated_at/last_used_at/use_count; document_type/source_document/engine_origin; confirmed_by_user/is_template. Таблица `fuzzy_keys` содержит вспомогательные ключи кандидатов; `metadata` — ревизию данных для кеша.

Unique: пара языков + нормализованный источник + перевод + domain + context + признак шаблона. Разные переводы одного источника сохраняются отдельно. Повторный импорт не размножает ту же запись и не снимает REJECTED. Повторная явная смена статуса доступна через repository API.

Настройки SQLite: WAL, synchronous FULL, foreign keys, busy timeout 250 мс, trusted_schema OFF. SQL-значения передаются параметрами, поля импортируемых записей проверяются по разрешённому набору. На операцию создаётся отдельное соединение; общего cursor между потоками нет. Локальные операции сериализуются RLock, разные экземпляры координируются SQLite. Проверен конкурентный сценарий четырёх потоков с отдельными экземплярами памяти.

## 3. Индексы и пакетный поиск

`tm_exact` — language pair + SHA256 источника; `tm_normalized` — language pair + SHA256 нормализованного источника. Дополнительно domain/status, status, last_used_at; уникальный составной индекс и ключ fuzzy_keys(pair,key,unit_id).

После hash lookup сравнивается сам текст, а не только хеш. Реальные EXPLAIN QUERY PLAN на всех размерах корпуса показывают SEARCH USING INDEX для exact/normalized, без полного сканирования units. Планы сохранены в benchmark JSON.

`lookup_many()` группирует хеши и делает SQL IN-запросы по 300 ключей. Документы прогревают память партиями по 256 сегментов; дальнейшие обращения используют общий bounded LRU. Кеш: 1024 результата, включая miss; ключ учитывает пару, domain/context, ревизию обеих баз и policy. Запись/импорт/изменение статуса меняет ревизию. Обновление use_count не сбрасывает все hot matches; изменение ранга только из-за использования станет видно после вытеснения/изменения данных.

Stats API возвращает числа записей/статусов, языковые пары, domains, lookup counters и размер кеша. Hit/miss учитывают вызовы поиска, в том числе prefetch; это не число сэкономленных inference. `reused` считает фактическую выдачу TM-результатов через обёртку, а use_count/last_used_at хранятся у пользовательской записи.

## 4. Нормализация и защита

Детерминированная normalization v1: Unicode NFKC, схлопывание пробелов/переносов, унификация типографских кавычек. Регистр, знаки препинания, дефисы и цифры не удаляются. ITM-1/ITM-2, 6.6/5.5 и 45–60/40–60 остаются различными.

Любой автоматически используемый результат, включая CONFIRMED exact, проходит существующий `faithful_result` и дополнительную проверку полных идентификаторов, URL/email, чисел, процентов и диапазонов. Слишком консервативный отказ допустим: он ведёт к модели, а не к ошибочной подмене. Числа в подтверждённом переводе могут записываться с запятой, но прежний fidelity guard восстанавливает написание числа из источника.

Подстановка не выводится из похожих обычных фраз. Нужен **явно подтверждённый шаблон** через `remember_template`, ровно с одним `{NUMBER_1}` в обеих частях. Несколько чисел, неоднозначное сопоставление и автоматическая подстановка идентификаторов/единиц не поддерживаются. Пример:

```python
memory.remember_template(
    'Fill {NUMBER_1} liters of coolant.',
    'Залейте {NUMBER_1} л охлаждающей жидкости.', 'en', 'ru')
```

Вход `Fill 6.6 liters of coolant.` даёт `Залейте 6.6 л охлаждающей жидкости.`. Склонение «литр/литра/литров» не генерируется: автор должен подтвердить грамматически пригодный шаблон. Это сознательное сужение подстановок ради безопасности.

## 5. Fuzzy, ranking, trust и domain

Кандидаты ищутся по шести детерминированным минимальным хешам символьных триграмм, с ограниченным числом строк на ключ. Оценка: 80% character SequenceMatcher + 20% пересечение word tokens; для китайского используется character score. Это мера сходства, не вероятность правильности. Для строк длиннее 2000 символов дорогой fuzzy-score пропускается; exact/normalized доступны до лимита записи 20000 символов.

Default fuzzy threshold 0.65, reuse threshold 0.98, **fuzzy_reuse=false**. Кандидат доступен через API MemoryMatch с score/type/trust/domain/pair/store/reusable. При разрешении fuzzy reuse нужны доверенный статус, порог и проверки чисел/идентификаторов. Аргос/M2M100 не получают подсказки через выдуманный prompt API: неподходящий кандидат просто не используется.

Порядок ранжирования: безопасность результата, тип совпадения, подтверждение в пользовательской памяти, вес domain/trust/context, similarity, quality, use_count, updated_at и стабильный id. Для равного уровня совпадения пользовательское подтверждение имеет приоритет. Domain-specific записи доступны своему domain; general служит общим fallback. Непустой context используется только при совпадении контекста. Разные языковые пары изолированы.

Статусы CONFIRMED, REVIEWED и IMPORTED доверенные; AUTO и REJECTED не используются. Import без `--trusted` создаёт AUTO. Даже trusted import создаёт IMPORTED, а не выдаёт чужое утверждение за локальное подтверждение пользователя. Trusted importer не отменяет ранее отклонённую запись.

Fuzzy-поиск ограничен по времени/числу кандидатов и **не гарантирует полный recall** на очень похожих больших корпусах: распространённые триграммы могут скрыть более поздние записи за лимитом. Это ограничение не влияет на индексированный exact/normalized lookup. Полноценный поиск всех альтернатив и редактор — будущая работа; текущий lookup возвращает лучшего кандидата, альтернативы хранятся в базе.

## 6. Пользовательская и встроенная память; Glossary

`builtin_path` подключает отдельную SQLite строго через mode=ro. Пользовательские изменения и счётчики никогда не записываются в неё. База со встроенными знаниями сейчас не поставляется и не наполняется. Проверены lookup builtin и приоритет пользовательского подтверждения.

`TranslationKnowledgeEngine` — общая точка расширения. `GlossaryProvider` и `GlossaryEntry` задают будущий контракт терминов (пара, domain, case_sensitive, whole_word, priority, notes, status). Термины не смешаны с translation units; реальное применение constraints отложено до AW0.7.1.

## 7. Import/export и обслуживание

`.tmemory` v1 — UTF-8 JSON Lines: заголовок format/version/schema_version/language_pairs/domains/provenance, затем записи. Такой формат можно читать/писать потоково. Ограничение входного пакета 256 МиБ; импорт одной транзакцией, некорректная запись отменяет весь импорт. Export публикуется через временный файл, flush/fsync и replace. Private source_document не экспортируется; служебные id/hash/use_count не переносятся как авторитетные данные. Даты вставки в новую базу устанавливаются заново. Экспорт содержит сами переводы и контекст, поэтому выполняется только явной командой.

Базовый TMX 1.4/1.4b реализован по [спецификации TMX 1.4b](https://www.ttt.org/oscarStandards/tmx/tmx14b.html): UTF-8, header/body/tu/tuv/seg, xml:lang, srclang, текстовые сегменты и domain property. Поддержаны пары из многоязычного tu; при неоднозначном *all* нужен явный source_language. Inline-коды, DTD/entities, UTF-16 и произвольные диалекты не поддержаны и отклоняются. Ничего не загружается из сети для XML.

API/CLI: stats, duplicates, integrity, optimize, vacuum, backup, restore; импорт/экспорт tmemory/TMX; explicit dataset export только CONFIRMED нетемплейтных пар. VACUUM выполняется только явно. Backup использует SQLite backup API, включая согласованное состояние WAL. Restore проверяет integrity/schema, сохраняет отдельную `tm-before-restore-*.db`, восстанавливает через SQLite backup API, обновляет ревизию кеша. Восстановление — явная административная операция, которую следует выполнять между заданиями; это не автоматическое исправление повреждённой базы. Проверено восстановление поверх читаемой базы. Поверх нечитаемой SQLite восстановление может остановиться на сохранении резервной копии: повреждённый файл нужно сохранить отдельно и выбрать новый подготовленный путь.

## 8. Privacy и отказы

Ни один метод TM не обращается к сети. Общая обёртка сохраняет offline_scope движка. В логах TM нет source/target; предупреждение о недоступной базе общее. На странице текста отображается «Память переводов», а при отказе TM — предупреждение в существующем статусе. На странице файлов переиспользован имеющийся warning/notice. Новые UI-компоненты не создавались.

При повреждении, busy timeout, ошибке миграции или неизвестной схеме TM временно отключается до retry/перезапуска, перевод моделями продолжается. База автоматически не удаляется. Отдельно проверены mock-router fallback при corrupt DB, запрет выдачи результата после cancel и отсутствие сетевых вызовов в TM.

SQLite **не зашифрован**. Защита локальных файлов зависит от прав учётной записи Windows; шифрование не заявляется. Размер сохранённого сегмента ограничен, целые документы дополнительно не собираются. Source_document/reference записывается только при явном вызове API.

## 9. Производительность

Временная benchmark DB удалена после измерения. Cold означает пустой **прикладной LRU**, а не холодный дисковый кеш ОС. По 7 замеров одиночных операций, по 3 пакетных; ниже медианы, миллисекунды. Новые TM-тесты: [tm-tests.xml](qa/aw07/tm-tests.xml). Покрывают создание/повторное открытие/миграционный отказ, индексы, Unicode/Chinese/Cyrillic/quotes/whitespace, punctuation/case, числа/диапазоны/идентификаторы, статусы/домены/контекст, альтернативы/дубликаты, шаблоны, fuzzy policy, language isolation, кеш и внешнюю запись, builtin readonly, обмен/TMX/DTD, backup/restore/integrity, concurrency, offline/log privacy и corrupt fallback.

Сквозной тест: первый запрос вызывает mock Router и не сохраняет результат; после явного remember второй запрос возвращается из TM, Router spy больше не вызывается. Документный тест использует один engine, 5 вручную заданных units, реальный DOCX, native PDF и raster PDF с настоящим PaddleOCR на CPU. Проверены перевод в выходных файлах, 0 вызовов модели на TM-hit, 5 исходных units без автоматического пополнения и SHA256 оригиналов.
