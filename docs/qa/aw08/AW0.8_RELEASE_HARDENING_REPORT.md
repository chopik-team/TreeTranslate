# TreeTranslate AW0.8 — Release Hardening, Performance & Translation Quality

Дата: 28 сентября 2026. Проверка локальной рабочей копии, без новых моделей и наполнения knowledge base.

## 1. Executive summary

AW0.8 завершает ограниченный цикл стабилизации поверх AW0.7.7. Найдено 11 проблем: BLOCKER 0, HIGH 4, MEDIUM 4, LOW 1, QUALITY_BACKLOG 2. Исправлено 8; осталось 3 с обоснованием ниже. Это не сертификация точности машинного перевода и не начало packaging.

Главные результаты: сохранение запрета после вопроса, проверка повреждённого вывода и отрицательных чисел, отзывчивое закрытие окна, устранение повторного inference одинаковых фрагментов и повторной загрузки PPStructure. Источник результатов — JSON/XML в этой папке, а не оценки по впечатлению. Реестр: [findings.json](findings.json).

## 2. Release blockers found

BLOCKER не обнаружены. HIGH: Argos терял запрет после вопроса; decoder artifacts принимались как перевод; закрытие активного окна блокировало GUI; потеря знака отрицательного числа принималась без ошибки. Все четыре исправлены. Ошибки смысла существующих моделей перечислены отдельно от ошибок нашего pipeline.

## 3. Release blockers fixed

- Argos разделяет текст после вопроса/восклицания, сохраняя исходные пробелы и переносы; обычные точки и сокращения не разбиваются новым правилом. Пример: `Did she check both valves yesterday? Do not start the pump.` теперь сохраняет «Не запускайте насос».
- Router проверяет вывод внутри существующего fallback: пустота, decoder tokens, недопустимые символы и потеря отрицательного числового значения вызывают следующий локальный backend либо понятную ошибку. Отмена не запускает fallback.
- При закрытии занятого окна GUI продолжает обрабатывать события до подтверждения worker. Сохранены восстановление незавершённой задачи и lifetime окна; старый mock service совместим.
- Регистр однозначно указанных имён файлов и команды `python` восстанавливается только при наличии соответствующего токена. Ничего отсутствующего в переводе не выдумывается.
- Одинаковые token chunks переводятся один раз в пределах запроса. Порядок, все повторения и разделители сохраняются; между запросами кэш не создаётся.
- Подробности языков создаются при первом открытии. Плитки и пользовательская последовательность вкладок сохранены.
- В OCR worker переменная цикла `table_models` больше не перезаписывает ключ кэша PPStructure. Дополнительные модели в памяти не удерживаются.

## 4. Remaining issues

LOW: минимальная фактическая высота «О проекте» — 987 px; отдельная адаптация для малых экранов нужна без отмены утверждённой сетки плиток.

QUALITY_BACKLOG: смысловые ошибки существующих моделей и сложный числовой ZH→RU пример; покрытие технических терминов и падежное согласование glossary enforcement. Изменение моделей/морфологии выходит за этот цикл. Не осталось открытых BLOCKER/HIGH/MEDIUM из реестра.

## 5. Translation quality

Создан оригинальный корпус 80 случаев: 12 категорий × 6 основных направлений плюс 8 случаев EN↔DE/ES/FR/JA. Категории: обычные фразы, грамматика/запрет, числа и единицы, техника, software, смешанный текст, сокращения, пунктуация, длинная фраза, абзацы, неоднозначность, повторяемость. Автопроверки не требуют дословного совпадения с эталоном.

Baseline **76/80 hard-pass**, итог **79/80**. Проверяются числа со знаком, единицы, пути/команды, разделители, запрет, Unicode, пустой вывод и runaway repetition. Первоначальная проверка чисел уточнена: тысячные разделители нормализуются, знак минус не отбрасывается.

| Направления | Итог hard-pass |
|---|---:|
| EN→RU, RU→EN, RU→ZH, EN→ZH, ZH→EN | по 12/12 |
| ZH→RU | 11/12 |
| EN→DE, DE→EN, EN→ES, ES→EN, EN→FR, FR→EN, EN→JA, JA→EN | по 1/1 |

Единственный непрошедший случай ZH→RU с отрицательным числом, датой и временем **безопасно отклонён**: основной backend теряет минус, fallback теряет другие числа. Это контролируемая ошибка, а не корректный перевод; 100% успешности не заявляется. Проверка чисел ограничена описанными формами и не доказывает числовую корректность любого текста.

Ограниченный семантический разбор агентом 27 примеров: 14 GOOD, 3 ACCEPTABLE, 10 NEEDS REVIEW; 53 не оценены семантически. Независимой экспертной оценки нет. Примеры модельных ошибок: ZH→RU `阀门` превращается в «вентиляторы»; crane/beam в неоднозначной фразе теряют значение; EN→ZH continuous casting превращается в spraying; ZH→EN casting — в welding machine. Это реальные слабые места, которые hard-pass сам по себе не обнаруживает. Они воспроизводятся в модельном выводе, отдельно от исправленной потери второй инструкции pipeline.

Существующая knowledge QA: automotive — 6 фраз, 0 совпадений, fidelity 2/6 до и после; metallurgy — 3 enforced термина, встречается «Проверьте легированная сталь». TM и glossary остаются активны и для обычного текста; проверки интеграции входят в regression. Новые корпуса/пакеты не добавлены. См. [translation-quality.json](translation-quality.json), [semantic-review.json](semantic-review.json), `knowledge/`.

## 6. Performance baseline

Windows 11 build 26200; Ryzen 7 5700X; RTX 3080 12 GB, driver 610.88; RAM 31.9 GiB. Python 3.12.13, PySide6 6.11.1, CTranslate2 4.8.2, Argos 1.11.0, SentencePiece 0.2.2, PDFium 5.13.0.

13 строк матрицы, отдельный процесс на строку, первый cold call, 1 прогрев, 3 измерения warm (медиана). CPU/GPU/Auto; все 6 профилей на ZH→RU. Нет output cache. Длинные нагрузки содержат повторяющиеся абзацы: ускорение нельзя переносить на произвольный уникальный текст. До production edits сохранены `build/aw08/baseline.zip`, SHA256 и Git diff. Текстовый и документный baseline сняты до исправлений; UI baseline снят до UI-оптимизаций, но после первых исправлений валидации/границ текста.

## 8. Memory

В текстовой матрице максимальный sampled peak RSS 811.4 MiB, loaded RSS до 497.5 MiB. UI idle 155.4 MiB; после пяти текстов RSS 614.34→614.59 MiB, после DOCX/PDF/OCR/отмены до 714.6 MiB. Плато на короткой серии не доказывает отсутствие долговременных утечек. Нативные allocator arenas могут сохраняться после shutdown.

В документах максимум суммы RSS родителя и OCR child — 2350.2 MiB. CPU измерен как process CPU seconds родителя, не как загрузка всего дерева в процентах. GPU device-total snapshots в итоговой текстовой матрице: 2071–2359 MiB при загруженной GPU-модели; после shutdown первой строки 1815 MiB. Это **вся видеокарта**, включая другие приложения, не peak VRAM процесса и не сопоставимый чистый прирост модели. В OCR JSON отдельно записаны Paddle allocated/reserved peaks.

TM benchmark: 10 000 синтетических изолированных записей; exact 3.08 ms, normalized 3.08 ms, fuzzy 3.89 ms, hot 1.73 ms, batch1000 103.76 ms. Glossary10000: exact4.27 ms, 100 terms23.72 ms; integrity/index checks проходят. Пользовательские базы не наполнялись.

## 9. OCR

Scan PDF end-to-end/page: CPU12.75/12.42 s, GPU8.67/8.51 s. Mixed8.47 s, rotated90°8.68 s, poor110dpi8.70 s. Это отдельные DocumentJob с запуском worker; второй такой прогон не называется warm inference. Извлечение/OCR6.7–11.3 s доминирует над переводом и записью.

Отдельная таблица, один worker на два обращения: Fast cold6.21 s, warm0.068 s; Maximum cold20.42 s, warm**0.221 s** вместо14.343 s до исправления (**−98.5%**). Cold практически не изменился. Полный распознанный текст и числа совпадают: `Parameter Value Voltage 220 V Length 42 mm Pressure 12 bar`. Сравнение: [ocr-table-baseline.json](ocr-table-baseline.json), [ocr-table.json](ocr-table.json). Новых моделей и OCR backend нет.

## 10. Documents

13/13 реальных DOCX/PDF/OCR прогонов завершены; исходные SHA сохранены, выходные документы повторно открываются. DOCX проверяет таблицу, абзацы, header/footer; PDF — изображения, размеры/страницы и извлекаемый результат. DOCX cold1.979→1.786 s; warm median0.842→0.747 s. NativePDF warm0.739→0.711 s. Запись PDF около0.37–0.40 s, перевод около0.30–0.71 s. Для небольших fixtures это наблюдение, не универсальный норматив на страницу.

Структурная целостность не означает точности перевода: например `Record 123 and 42 mm` даёт «Рекордные 123 и 42 мм». Оригинал и числа сохранены, смысл требует проверки. [documents-final.json](documents-final.json) содержит все transcripts и timings.

## 11. Router/profiles

ZH→RU GPU warm: Economy152.5, Fast182.8, Automatic194.4, Balanced208.2, Turbo183.5, Maximum210.3 ms; профиль не является оценкой качества перевода. Матрица фиксирует фактический backend/device/route/fallback. EN→FR Economy работает через доступный M2M100. Политика 42 направлений × 6 профилей покрыта существующими тестами; реальный AW0.8 корпус оценивался в Balanced, семантическое превосходство одного профиля не доказано.

Повреждённый `<unk>` теперь вызывает локальный fallback; отсутствие обоих приемлемых результатов возвращает ошибку. Проверки отсутствующих/повреждённых моделей и отмены сохранены. Бесконтрольных retry нет.

## 12. Offline

Quality, document и OCR probes: 0 наблюдаемых попыток сети под установленными guards; OCR запрещает model-hub lookup. 15 локальных моделей проверены по манифестам/SHA256 ([model-verification.txt](model-verification.txt)). Это локальные проверки, не внешний сетевой аудит. Новые зависимости, загрузки моделей и внешние сервисы не добавлены.

## 13. UI responsiveness

«О проекте»: median256.5→56.8 ms (**−77.9%**, 3 открытия). Settings87.0→81.5 ms. Startup1369→1136 ms — одиночное наблюдение, не гарантия. Heartbeat10ms: максимальные интервалы text22.6ms, DOCX24.2ms, PDF54.9ms, OCR57.0ms.

На синтетическом native call300ms вызов close раньше блокировал302.6ms, теперь возвращает за0.096ms; фактическое закрытие после подтверждения занимает339ms. Реальная отмена длинного текста около3.01s: native inference прерывается кооперативно на границе вызова, не мгновенно. Pause/resume, двойной старт, stale result, отмена/close/restore проверены regression. Визуального redesign нет; единственная UI-переработка — ленивое создание существующих подробностей ради времени открытия.

## 14. Tests

Адресный набор: **86 passed**. Полный итоговый regression: **549 passed**, после последней правки OCR. Реальный повторный OCR probe подтверждает повторное использование PPStructure и совпадение текста. `compileall app tools` и `git diff --check` — успешно. Итоговые статусы: [validation.json](validation.json), [full-tests.xml](full-tests.xml).

Ошибки/надёжность: corrupt/encrypted PDF, отсутствующие модели и checksum, pause/cancel, отказ записи/PermissionError без traceback/приватных путей, сохранность исходников, локальный fallback, offline, закрытие/restore — [error-matrix.json](error-matrix.json). Проверки PermissionError/OSError используют fault injection; физическое заполнение диска не выполнялось.

## 16. Post-W1.0 backlog

Отдельная адаптация «О проекте» к малым экранам; экспертный многоязычный corpus и проверка неоднозначных технических фраз; безопасное улучшение numeric coverage; morphology-aware glossary и точечное покрытие терминов. Долговременный memory soak и более широкий аппаратный benchmark остаются будущими проверками. Новые языки/модели, обучение, morphology overhaul, installer и AW0.9 не начаты.
