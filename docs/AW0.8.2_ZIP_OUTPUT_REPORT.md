# AW 0.8.2 — ZIP input → translated ZIP output

Дата: 1 октября 2026. Область: ZIP-контейнер; OCR, модели, терминология,
glossary, auto-domain и PDF layout не изменялись. Автоматических commit нет.

## Аудит и прежнее поведение

Изучены scanner, DocumentJob, SourceFile, встроенное именование и выделение
каталогов, настройки имён/места результата, коллизии, публикация, JobControl,
ProgressPanel, FilePicker, DropZone, дерево, восстановление задачи и тесты.
Production scan_sources принимал отдельные DOCX/PDF и каталоги; ZIP/RAR
попадали в skipped. Надписи/пример ZIP в старом mock UI не означали
наличие production распаковки. Архивного writer не было.

## Новый контракт и архитектура

- Отдельный DOCX/PDF остаётся отдельным документом; каталог сохраняет прежнее поведение.
- Выбранный ZIP даёт новый ZIP. До публикации итогового архива временные PDF/DOCX
  не попадают в output actions и не объявляются пользовательскими результатами.
- Preview читает проверенный inventory, создаёт виртуальные SourceFile для участников;
  распакованные файлы не нужны до запуска перевода. Исходные ZIP-пути сохраняются
  для восстановления незавершённой задачи.
- `zip_archive.py` отвечает за безопасность, bounded extraction, CRC, упаковку
  и publication. `archive_job.py` — адаптер контейнера вокруг того же DocumentJob.
  `_run_documents` использует прежние backends, OCR, PDF/DOCX writers и validators.
  Второго переводчика или document pipeline нет.
- Именование файла выделено из `_destination` в общий `_filename`; он используется
  также для ZIP. DocumentJob принимает внутренний destination override, чтобы
  размещать документы в структуре временного output без лишнего root-каталога.

## Безопасность и неизменность

Проверяются все записи до извлечения; небезопасная запись отклоняет весь архив.
Проверки: абсолютные пути, traversal, обратные разделители, пустые/точечные компоненты,
ADS/недопустимые Windows-символы и reserved names, окончания точкой/пробелом,
дубли (NFC + casefold), конфликт файла и каталога, symlink/special/reparse-like entries,
шифрование, повреждение/CRC и лимиты. Отдельное извлечение никогда не использует
непроверенный путь и дополнительно проверяет containment внутри workspace.

Консервативные пределы: ZIP 256 MiB, 10 000 entries, суммарно 1 GiB распакованных
данных, 256 MiB на entry, отношение сжатия входа ≤200, путь ≤1024 символов,
глубина ≤32 компонента. После упаковки допустимы хорошо сжимаемые обычные assets:
их известный размер уже ограничен; входной bomb-порог не применяется повторно
к собственному сжатию, остальные ограничения сохраняются.

SHA256 ZIP фиксируется при сканировании и перед job, проверяется после извлечения,
до/внутри публикации и после cleanup, в том числе после отмены. Архив открывается
только для чтения. Workspace — приватный `%TEMP%/TreeTranslate-zip-<id>`;
он очищается после success/error/cancel. Пользовательская распакованная папка
рядом с оригиналом не создаётся.

## Имена, структура и комплектность

- Stem переводится отдельно от extension; применяется существующий hotfix
  повторных расширений и safe fallback. ZIP-имя следует настройке перевода имён
  файлов; `{name}_{lang}` сохраняется. Generic output name не вводится.
- Внутренние каталоги переводятся только при включённой настройке. Cache:
  исходный component + source/target; одинаковый component переводится один раз
  за ZIP-job. Логическая иерархия и пустые каталоги сохраняются.
- Коллизии внутри parent разрешаются суффиксами `(1)`, `(2)` и т.д.; учитываются
  NFC/casefold и имена копируемых assets. Переведённый каталог не занимает имя
  неизменяемого файла. Внешний ZIP также получает свободное имя без перезаписи.
- Неподдерживаемые обычные файлы и вложенные ZIP/RAR копируются байт-в-байт;
  рекурсивной распаковки нет. PDF/DOCX, снятые пользователем с выбора, также
  сохраняются unchanged, чтобы комплект не исчезал.
- Поддерживаются Unicode filenames, повторное открытие и UTF-8 flags.
  В отчёт/лог попадают translated_files, copied_unchanged и skipped_unsafe;
  небезопасные ZIP отклоняются целиком, поэтому успешный результат имеет unsafe=0.

## Validation, публикация и управление

Каждый выбранный документ проходит обычный DocumentJob и его strict validator.
ZIP собирается с DEFLATE во временный `.treetranslate-*.zip`, полученный через
exclusive mkstemp в каталоге назначения. Проверка повторно открывает ZIP,
читает содержимое с CRC, проверяет пути/дубли, непустой inventory, ожидаемое число
и точное множество entries. Затем JobControl.publish выполняет no-clobber rename
на Windows (link/unlink на иных ОС), с повторной проверкой SHA исходника.

Ошибка выбранного документа/валидации отменяет весь ZIP: неполный архив не выдаётся.
Pause/resume сохраняет JobControl semantics; checkpoint есть в потоковом чтении,
распаковке, копировании, упаковке, CRC и обычном переводе. Cancel прекращает новые
операции, предотвращает publication и удаляет временные данные. Готовые результаты
других независимых входов в mixed batch сохраняются по прежнему правилу.

Переиспользованы ProgressPanel, FileTree, output actions и настройки. Добавлены
только стадии подготовки/сборки/проверки архива и DOCX/PDF/ZIP в существующем picker
и DropZone. 100% ставятся после итоговой публикации; финальный счётчик сохраняет
365/365, а не сбрасывается на значение по умолчанию. При неизвестных архивных
операциях ETA уточняется; они не считаются translation segments. «Открыть файл»
использует итоговый ZIP, «Открыть папку» — его parent. Новые подписи и ошибки
переведены вручную в восьми имеющихся locales. Отдельного Archive UI нет.

В documents.log записаны archive_open, archive_validate_input, archive_extract,
archive_scan, archive_translate, archive_pack, archive_validate_output,
archive_publish, archive_cleanup с длительностями. Вложенные времена включительные,
их нельзя складывать с родителями. Последующие output member checks имеют отдельный
tag, чтобы не смешивать проверку входа с повторным использованием inventory validator.
Метаданные содержат ZIP source/container и member path; тексты не логируются.

## Тесты и ограничения

Targeted ZIP tests покрывают ZIP→ZIP, DOCX content, вложенные/пустые каталоги,
Unicode, stems и настройки имён, once-only extension, folder cache, коллизии,
копируемые assets/вложенный ZIP, unsafe/duplicate paths, encrypted/corrupt ZIP,
CRC, ресурсные пределы, ошибку перевода/validation, source mutation, cancel при
переводе и упаковке, pause/resume, atomic publication race, внешний collision,
очистку и source SHA. Existing document tests не ослаблялись.

Последняя широкая регрессия: 186 passed за 54,65 с (ZIP, PDF, OCR, UI,
coordination, настройки и журнал). После усиления резервирования имён,
ownership временного ZIP, pause/collision checks и mixed folder+ZIP: 49 passed за 6,52 с
(ZIP tests + measurements + settings/locales). Семантика обычных документов сохранена.

RAR writer/reader и внешние архиваторы не добавлены. ZIP внутри выбранной папки
остаётся прежним неподдерживаемым файлом сканера; ZIP как отдельный выбранный вход
поддержан. Вложенные архивы копируются. Продолжение после ошибки внутри ZIP начинается
заново: контейнер публикуется целиком, временные документы после ошибки удаляются.
Ручная распаковка папки не маркируется как ZIP без достоверной provenance.

Все пункты ZIP acceptance gate выполнены для контрольного корпуса. Дальнейшие
OCR quality, automotive terminology и PDF performance изменения не начинались.
